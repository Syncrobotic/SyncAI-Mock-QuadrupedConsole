# SyncAI Quadruped Console — Design System

給做這個 App 的設計與前端。規則都是從實際審查中定出來的，每條附上原因。和 dashboard 共用的 tokens（`src/styles/tokens.css`）以 dashboard 為準，本文件只寫 Console 自己的規則與偏離。

---

## 1. 原則

1. **極簡**：一頁一個重點——一個主視覺、一行標題、最多一行副標、一顆主按鈕。超過一行的說明放到點擊後才出現的對話框。
2. **位置不動**：同一類元素在每一頁都在同一個位置（主按鈕、進度條、返回、略過）。
3. **安全區優先**：任何文字與按鈕都不能落在瀏海、動態島、打孔、Home 條、導覽列底下。
4. **深淺色都達標**：兩種主題的文字對比都 ≥ 4.5:1（大字 ≥ 3:1）。
5. **先驗證再交付**：四種裝置 × 兩種主題截圖看過，審查腳本全過，才算完成（§10）。

## 2. 安全區

| 規則 | 做法 |
|---|---|
| 唯一來源 | 一律用 `var(--safe-top/right/bottom/left)`，**不要直接寫 `env(safe-area-inset-*)`**。真機上它等於 `env()`；桌面審查外框依模擬裝置覆寫；原生殼層（舊 Android WebView 拿不到 env）也可以直接設定這四個變數。 |
| 背景延伸、內容內縮 | 背景、地圖、光暈延伸到瀏海與 Home 條底下；文字、按鈕、進度條從安全區內開始。 |
| 上方 | 頂列從 `--safe-top` 開始。 |
| 下方 | 主按鈕底部距離 = `max(16px, --safe-bottom + 8px)`；鍵盤出現時改為鍵盤高度。 |
| 橫式 | 所有控制項放在依四邊安全區內縮的圖層；地圖仍然滿版。E-Stop、搖桿不可落在瀏海側。 |
| 對話框 | 在安全區內置中；靠近 E-Stop 的一側不需額外留白（E-Stop 永遠不被蓋住）。 |
| Toast | 從狀態列下方 12px 開始（Console 內改在 E-Stop 上方）。 |
| 底部手勢區 | 底部 16px 內不放需要拖曳的元件（避免和系統手勢衝突）。 |

**桌面審查外框**（審查面板 → 預覽）模擬的裝置與安全區（CSS px）：

| 裝置 | 直式 上 / 下 | 橫式 左 / 右 / 下 | 特徵 |
|---|---|---|---|
| iPhone 16 Pro（預設） | 62 / 34 | 62 / 62 / 21 | 動態島、Home 條；橫式隱藏狀態列 |
| iPhone SE | 20 / 0 | 0 / 0 / 0 | 無瀏海、實體 Home 鍵 |
| Pixel 9 | 48 / 24 | 48 / 0 / 24 | 中央打孔、手勢條 |
| Galaxy S24 | 36 / 48 | 36 / 48 / 0 | 打孔、三鍵導覽列（橫式在右側） |

狀態列文字與 Home 條顏色跟隨主題（深色主題白、淺色主題黑）。

## 3. 觸控與尺寸

- **觸控區 ≥ 44×44**：所有按鈕、分頁、開關自動加上看不見的 `::after` 延伸區（`globals.css`），**外觀可以小，觸控區不行**。`data-no-slop` 可以關掉。
- 輸入框無法加延伸區：高度 40px；若更小，用 `<label>` 包住並加 2px 內距補到 44。

| 元件 | 高度 |
|---|---|
| 主按鈕（引導流程） | 44 |
| 一般按鈕 default / sm / lg | 36 / 32 / 40 |
| 輸入框 | 40（字級 14px，避免 iOS 聚焦時自動放大） |
| 下拉選單 | 外觀 36，隱形原生層 46 |
| 資訊列（卡片內） | 最小 36 |
| E-Stop、搖桿、姿態鍵 | 不縮小（安全相關） |

## 5. 引導流程（連線）骨架

每一頁都是同一個骨架，由上到下：

```
┌───────────────────────────────┐
│ [左槽 48]  ▬▬ ▬▬ ▭▭ ▭▭  [右槽 48] │  頂列：返回/取消 · 分段進度 · 略過
│                               │
│          （主視覺）             │  ┐
│           標題 20px            │  │ 整組在頂列與底部之間垂直置中
│          一行副標 13px          │  │
│        （選項卡 / 表單）         │  ┘
│                               │
│         更換金鑰（文字連結）      │  主按鈕上方的替代動作（選用）
│  [          主按鈕           ]  │  唯一的底部按鈕，位置固定
└───────────────────────────────┘
```

### 5.1 底部：只有一顆主按鈕

- 每頁底部**只有一顆主按鈕**，永遠在同一個位置。**不要**在它下面或旁邊放第二顆按鈕。
- 自動進行的步驟也顯示主按鈕：停用 + 進度文字（「連線中…」「登記中…」），不要讓按鈕忽有忽無。

### 5.2 次要動作放哪裡

| 類型 | 位置 | 例 |
|---|---|---|
| 跳過這一步 | 頂列右槽，文字 | 略過（Wi-Fi） |
| 換一種輸入方式 | 頂列右槽，圖示 | 掃描授權卡（金鑰頁） |
| 取消進行中的自動步驟 | 頂列左槽，✕ 圖示 | 配對中、等狗上線、更換金鑰 |
| 返回上一步 | 頂列左槽，‹ 圖示 | 找狗→初始、License→找狗、Wi-Fi→License、安全→Wi-Fi |
| 同一步的替代動作 | 主按鈕**正上方**的文字連結 | 更換金鑰 |
| 查看詳情 | 內容區文字連結，點開對話框 | 5 項功能全部開啟 › |
| 求助 | 內容區文字連結，**15 秒沒有操作才淡入** | 找不到你的狗嗎？ |

**每一步的左槽都有東西**：能回去的用 ‹，自動步驟用 ✕。只有初始畫面沒有頂列。

### 5.2.1 藍牙斷線（配對之後）

- 步驟本身不處理斷線；它們的藍牙呼叫會等連線回來再繼續，**已輸入的內容都保留**。
- 斷線時，底部唯一的按鈕變成停用的「重新連線中…」，背景每 3 秒重連一次。
- 15 秒還沒回來，按鈕變成「重試」。
- 不加任何說明文字、不跳對話框。

### 5.2.2 權限

- 權限只在**需要的那一刻**要，用系統自己的對話框，App 不另外加說明畫面。
  - 藍牙：按「開始配對」時。
  - 位置（讀手機目前的 Wi-Fi 名稱）：第一次進 Wi-Fi 頁時。
  - 相機：第一次按掃描授權卡時。
- **被拒時靜默降級，不擋流程**：位置被拒 → 不顯示「手機所在」、不預選、不顯示網路不一致警告，三節點圖示維持中性。

### 5.2.3 輸入

- 進頁**不自動彈出鍵盤**。鍵盤只在使用者點了之後才出現（例：點選 Wi-Fi 網路後，密碼欄才聚焦）。例外：這一頁只有一個輸入（金鑰）。
- 錯誤只標出**有問題的那一格**（金鑰：版本前綴錯 → 第 1 格；已綁定 → 0000 那一格），並輕微搖晃。

### 5.3 分段進度

- 4 段（配對 · 授權 · 網路 · 安全），每段 6px 高，和返回鍵同一行、垂直置中。
- 預設不顯示文字。**按住（或鍵盤聚焦）**才浮出「配對 · 第 1/4 步」，放開 1.2 秒後淡出。讀屏用 `aria-valuetext`。
- 左右兩個 48px 槽寬度相等，所以進度條永遠置中，不會和「略過」重疊。

### 5.4 選項卡（ChoiceCard）

選狗、選 Wi-Fi 等「從清單選一個」一律用同一個元件：

- 左：48×36 方塊（序號末四碼，或訊號強度圖示）
- 中：標題（可加一個小徽章，如「手機所在」）＋一行副標
- 右：單選圓點
- 選中：主色邊框 + 淡主色底；下一步需要的東西（例如密碼）**在同一張卡片裡展開**
- 不可選：半透明 + 副標註明原因（「暫不支援」）

### 5.5 主視覺

- 用同一套視覺語言：節點與中間的連線，或一個圖示底座（金鑰、授權完成）。
  - 配對：手機 — 狗。
  - Wi-Fi：手機 — 路由器 — 狗（連好之後手機是經路由器找到狗）。手機那段只在「已知手機在同一個網路」時是實線；已知不同 → 琥珀色虛線；不知道（權限被拒 / 手動輸入）→ 中性虛線。
- 不要突然出現風格不同的元件（例如漸層卡片）。

## 6. 動畫

| 項目 | 規格 |
|---|---|
| 換頁 | 單一層：滑入 24px + 淡入。進場 0.24s ease-out，離場 0.14s ease-in；返回時方向相反 |
| 結果出現 | 上移 8px + 淡入 0.3s；勾勾用 spring 彈出 |
| 清單 | 逐列 0.05s 錯開 |
| 持續動畫 | **只用在「正在進行」**：雷達掃描、連線光點、等待脈衝、Wi-Fi 進度環 |
| 減少動態效果 | `MotionConfig reducedMotion="user"` + 全域 CSS，自動停用 |

不要疊兩層動畫（例如標題自己再淡入一次），會出現半透明卡住的畫面。

## 7. 顏色與對比

- 顏色一律用 token（`text-status-ok`、`bg-primary` …），不要寫死色碼。
- **明亮模式的覆寫（與 dashboard 共用 tokens 的偏離）**：下列 token 在淺色背景上當小字使用時只有 3.8–3.9:1，Console 在 `globals.css` 把它們調深到 ≥ 4.5:1。之後應提回 dashboard 同步。

| Token | 共用值（light） | Console 覆寫 |
|---|---|---|
| `--status-ok` | oklch(0.54 0.145 150) | oklch(0.46 0.13 150) |
| `--severity-warning` | oklch(0.56 0.115 75) | oklch(0.48 0.11 70) |
| `--primary-accent` | oklch(0.464 0.15 285) | oklch(0.42 0.15 285) |
| `--status-error` | oklch(0.58 0.22 28) | oklch(0.5 0.2 25) |
| `--status-busy` | oklch(0.56 0.14 250) | oklch(0.47 0.13 250) |
| `--severity-info` | oklch(0.55 0.125 240) | oklch(0.47 0.12 240) |

- 深色背景上的地圖航點編號：依底色自動選黑字或白字。
- 停用的項目：虛線框 + 淡底，**不要**把文字變淡到看不清。

## 8. 表單

- 錯誤訊息放在欄位下方，加 `role="alert"`（讀屏會唸）。
- 用真的 `<form>`：鍵盤的「前往 / Enter」可以送出；底部主按鈕用 `form` 屬性連到表單。
- 密碼欄 `autoComplete="current-password"`、`enterKeyHint="go"`。

## 10. 驗證流程

1. `scripts/ux-audit.js`（Playwright）：走過引導流程每一步與 Console 所有畫面，**深色、淺色各跑一次**，檢查觸控區、對比、字級、無名稱按鈕、無標籤輸入框。結果必須為空。
   - 已知誤報：Console 選中的分頁（白字在 `ActivePlate` 紫底上），腳本看不到兄弟元素的底色，會報 1.03。
2. 審查面板切換四種裝置，直式與橫式各截圖，逐張看過沒有被擋住、沒有跑版。
3. `tsc`、`eslint`、`vitest`、`next build` 全過。
