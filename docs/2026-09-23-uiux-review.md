# UI/UX 審查 — Quadruped Console Mock

2026-09-23 · 對象：`a64adb2`

## 方法

用 Playwright 跑 `scripts/ui-audit.js`（Playwright MCP 的 `browser_run_code` 可直接載入），在兩種尺寸上實際量測，不是用看的：

- **iPhone 14 尺寸**：390×844 手機框
- **iPhone SE 尺寸**：375×667 全螢幕

範圍是 4 個 tab × 3 段 sheet 高度，加上幾個特殊狀態：通話中的畫中畫、狀態卡展開、`weak_signal`、`BleOnly`。量測項目：

- 浮動元件之間的重疊
- 觸控目標是否小於 44pt
- `.truncate` 文字是否被截斷
- 地圖面板的可視高度
- sheet 可視高度 ÷ 內容高度

另外補看淺色模式、Onboarding，並讀原始碼找結構性問題，例如 z-order 和安全區域。

嚴重度：
- **P0**：安全，或會擋住操作
- **P1**：遮擋，或核心流程變難用
- **P2**：觸控與排版
- **P3**：一致性與內容

## P0 — 安全 / 擋操作

### 1. 所有對話框都蓋住 E-Stop

- **證據**：`Modal` 是 `fixed inset-0 bg-black/55 z-50`，而 E-Stop 在它底下。包含 Owner 核准新手機（不能點外面關閉）、刪除任務、中止任務、撤銷手機、換 Wi-Fi、License 金鑰。
- **影響**：spec §5 要求「任何 tab 任何 sheet 高度都不被遮蓋」。對話框開著的時候，狗還在動，但 E-Stop 按不到。
- **建議**：
  - 遮罩改成停在 E-Stop 上緣，或把 E-Stop 抬到遮罩之上（z 大於 50）。
  - 對話框改成從 E-Stop 上方彈出，而不是從螢幕底部。

### 2. 沒有處理安全區域（瀏海、動態島、Home 條）

- **證據**：`viewport-fit=cover` 開了，但沒有任何 `env(safe-area-inset-*)` 內距。
- **影響**：在真機上，頂部狀態卡會被動態島或瀏海蓋住，sheet 最下方和 Tab 內容會被 Home 條壓住。
- **建議**：Console 根層加上 `pt-[env(safe-area-inset-top)]`、`pb-[env(safe-area-inset-bottom)]`，Onboarding 同樣處理。

### 3. SE 上操控 tab 摸不到姿態與步態

- **證據**：`SE 操控 snap1` 的 sheet 可視 266px，內容 360px。操控 tab 又鎖在 50%，拉不高。在 14 上是 344 / 360，也差一點。
- **影響**：站立、坐下、趴下、恢復和步態都在可視範圍外，必須在搖桿旁邊捲動 sheet，而捲動時容易誤觸搖桿。E-Stop 之後常常要「恢復」，偏偏這顆鍵藏起來了。
- **建議**：二選一：
  - 讀數板縮成單行，姿態鍵移到讀數板下方，把搖桿放在最下面。
  - 允許操控 tab 用 55% 到 60% 的高度。

### 4. 狀態卡展開後被裁切，而且被畫中畫蓋住

- **證據**：展開後的狀態細節底部在 337px，但地圖面板在 14 上只有 332px、在 SE 上只有 253px，面板是 `overflow-hidden`，所以被裁掉。畫中畫（z-20，DOM 順序在後面）直接疊在細節上。
- **影響**：「最近 5 條系統事件」看不到；排查連線問題時最需要的就是這一塊。
- **建議**：細節改成從狀態卡往下展開的 sheet，或高度不超過地圖面板並可捲動。展開時畫中畫要讓位或降低 z。

## P1 — 遮擋 / 可用性

### 5. sheet 拉到 90% 時，地圖只剩 57–73px，而且完全被頂部卡片佔滿

- **證據**：`任務/通話/裝置 snap2` 的 `mapH` 在 14 上是 73、SE 上是 57，頂部卡片疊起來也是 73px 高。檢視按鈕和電量卡重疊（44×44）。
- **影響**：地圖其實已經看不到了，卻還留一條被遮住的殘影。
- **建議**：90% 時把地圖面板收成一行精簡狀態列（狗名、電量、RTT），不渲染 canvas，也省電；或者把 90% 的上限調到地圖至少留 140px。

### 6. Banner 疊加吃掉地圖

- **證據**：
  - `BleOnly`：頂部區塊 176px。在 SE 上地圖只有 253px，等於蓋掉約 70%；檢視按鈕和 banner 重疊（44×29）。
  - `weak_signal`：117px。
  - License 到期 banner 在所有狀態都常駐。
- **建議**：
  - 同一時間只顯示一條最高優先的 banner，其餘收進狀態卡（「2 則提醒」）。
  - License 到期改成狀態卡上的小點，加上裝置頁提示，可以關掉。
  - 「離線 · 顯示最後快取」這個 chip 和 BleOnly banner 講的是同一件事，拿掉 chip。

### 7. 畫中畫會蓋到檢視按鈕，而且不能移動

- **證據**：SE 上「回到通話」和「跟隨」按鈕重疊（44×43）。
- **建議**：畫中畫可以拖曳並吸附到四個角，自動避開檢視按鈕和頂部卡片。SE 上縮小到 112px 寬。

### 8. 圖層選單往上展開，蓋到頂部卡片，而且切 tab 也不會關

- **證據**：淺色模式截圖裡，圖層選單疊在狀態卡和 License banner 上。
- **建議**：點外面或切 tab 時自動關閉；改成往左展開，貼齊按鈕列。

### 9. Toast 會蓋到頂部卡片

- **證據**：Toaster 設在 `top-center offset 56`，和狀態卡、banner 同一個區域。任務開始和結束、感知事件都會跳，巡邏時一直在跳。
- **建議**：Toast 改到 E-Stop 正上方；一般資訊類的事件（任務進度）不跳 toast，只進事件列表；只有 warning 以上才跳。

### 10. 跟隨視角幾乎只看得到牆

- **證據**：操控 tab 的跟隨視角，平面圖的牆是 2.6m 實心，畫面大部分是灰牆和地板，看不出周遭。
- **建議**：跟隨視角時牆改成半透明，或降到 1m；同時預設打開點雲（spec §6 的點雲本來就是為了感知周遭）；在狗前方畫一條行進方向的導引線。

### 11. 俯視時房間標籤被裁掉，或和按鈕重疊

- **證據**：地圖邊緣的「開放辦公區 B」「印刷室」被切掉，右側標籤和檢視按鈕疊在一起。
- **建議**：標籤只顯示在可視範圍內，並避開按鈕欄；縮放太遠時只顯示大區域的標籤。

### 12. 任務編輯器在 50% 只看得到約 2 個航點

- **建議**：編輯器頂部的標題列和儲存鈕縮成一行；航點列表改成緊湊的單行（編號、座標、動作數）；只有選中的航點才展開。

## P2 — 觸控目標 / 排版

### 13. Button 在寬螢幕時會縮小（從 dashboard 帶過來的問題）

- **證據**：姿態鍵在 14 手機框裡量到 47×32。`button.tsx` 的尺寸寫成 `h-10 md:h-8`，`md:` 是依整個視窗寬度判斷，所以在桌機手機框裡、以及 iPad 或 Android 平板（寬度 768 以上）上，都會縮成 32px。
- **建議**：手機 App 版的 Button 拿掉 `md:` 尺寸，所有尺寸至少 44。

### 14. 其他小於 44pt 的目標

| 元件 | 量到的尺寸 |
| --- | --- |
| Switch（任務啟用、plugin、SoftAP） | 36×20 |
| Select（角色、圍欄外行為、E-Stop 後趴下、步態） | 36px 高 |
| 改名鉛筆、撤銷 | 32–40px |
| 任務列可點區域 | 41px 高 |
| BleOnly banner 的「重試」 | 60×32 |

**建議**：把 Switch 的可點範圍擴大成整列，其他元件都補到 44px。

### 15. 文字截斷

- **證據**：
  - 裝置頁「小腦 cb-3.4.1 · Gateway gw-0.9.2」
  - 已配對手機的暱稱「夜班 · Pixel 8」「櫃台 · iPad」，被角色選單和撤銷按鈕擠掉
- **建議**：已配對手機列改成點整列 → 打開動作選單（改角色、撤銷），右側只放角色 pill。版本資訊拆成兩列。

### 16. 通話 tab 在 SE 50% 時，第二排控制鍵被切掉

- **證據**：可視 266px，內容 363px。
- **建議**：一排只放 4 個主要鍵（麥克風、按住說話、喇叭、結束），其他收進「更多」。

## 建議修正順序

1. **先修 P0 的 1–4**：E-Stop 永不被遮、安全區域、SE 操控版面、狀態細節。都是半天內可以做完的結構性修改。
2. **再修 P1 的 5–9**：90% 地圖收合、banner 只留一條、畫中畫可拖、圖層選單關閉、toast 移位。這幾項處理的都是「地圖被蓋掉」這一個問題。
3. **P1 的 10–12 和 P2**：視角、標籤、編輯器密度、觸控目標，可以一起做。
4. **P3** 需要產品決定（用語、mock 提示的顯示方式），列入待決。

每次修完重跑 `scripts/ui-audit.js`。目標是 overlaps 為 0、small 只剩刻意保留的元件、每個狀態的 sheet 可視高度都大於等於內容高度。
